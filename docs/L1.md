# Layer 1

Timecoin is a single-operator layer-1 testnet. A node checks each block from genesis. Version 0.2.0 has no gossip network and no mainnet parameters. Two processes can still exchange a block: the bytes carry the transactions, the coinbase, and the signatures, and the receiver re-executes them.

Original repository: <https://github.com/9lordisgod/Timecoin>

## Paths

```mermaid
flowchart TD
    wallet[Wallet builds a transaction]
    pool[Mempool applies it after the pool]
    propose[Proposer seals a block on the head]
    store[Store writes the block bytes]
    other[Second node re-executes from the parent]
    wallet --> pool --> propose --> store --> other
```

## State transition

```mermaid
flowchart TD
    parent[Parent state]
    tx[Apply transactions in block order]
    check{Inputs equal outputs plus fee, adjusted for call value and payout}
    coin[Insert coinbase of reward plus fees]
    mint[Add 50 TIC to supply]
    root[State root must match the header]
    parent --> tx --> check
    check -->|no| reject[Reject the block]
    check -->|yes| coin --> mint --> root
```

Only the reward increases supply. A fee is taken from the inputs and paid to the coinbase. The token is Timecoin and the ticker is TIC.

## Fork choice

```mermaid
flowchart TD
    tips[Tips that are not parents]
    height{Greater height}
    ident{Smaller block id}
    tips --> height
    height -->|one winner| head[Head]
    height -->|tie| ident --> head
```

An uncle is a block that shares its parent's parent and its parent's height. The child may cite at most two uncles. Uncle transactions are not applied.

## Notes

```mermaid
flowchart LR
    sender[Sender generates a one-time ML-DSA key]
    kem[ML-KEM-768 ciphertext to the view key]
    chain[Block stores the public amount and the ciphertext]
    scan[Recipient decapsulates and checks the MAC]
    sweep[Sweep spends the note into a fresh note]
    sender --> kem --> chain --> scan --> sweep
```

The long-term view key is not a block field. Amounts stay public so every node can reject inflation without a proof.

## Conflict waves

Transactions that do not share a note commitment, a nullifier, or a contract id commute. Overlapping transactions stay in listed order. The measured run puts two payments in one wave and a spend of a new note in a second wave. See `docs/charts/waves.png`.
